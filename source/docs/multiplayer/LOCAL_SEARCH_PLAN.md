# 多人本地搜索实施计划

目标：在不预测队友主动出牌、保持当前预算和本地执行权限的前提下，保留跨回合打法并减少外部变化造成的无效计算。用户要求先重构项目，再开始实施；当前阶段仅做代码层验证，不启动游戏。算法改动与“少量承伤换节奏”的目标函数实验分别验证，不以提高预算换取结果。

## 当前起点

- 对照提交 `19f7a559`，游戏/RitsuLib pinned 0.107.1。
- 默认 local-single-core，当前回合加后两回合，原始战损优先；队友预测/团队场景默认关闭。
- 已有跨回合候选保留、R0/R1、新根路线重放和工作统计，避免重复建设或放宽缓存键。
- 同回合 refresh 已接入既有后台搜索：保留最多三条、每条至多 128 动作的纯值路线，先完整重放当前路线，再重评至多两条完整备选；当前仍合法时也可以换优。全部未获准才回退到三组两动作前缀的物化或普通搜索。恢复阶段共用原 192 节点/60ms 软上限，失败后的主搜索使用请求剩余预算；根捕获仍在主线程，排空另计。
- 精确续用复制与独立跨回合恢复现已传递完整备选，按当前回合裁切动作并重建前缀；独立恢复沿用原准入，当前和备选共享原 600ms 软份额，失败后进入既有 R1/主搜索。恢复、主搜索和审计共用总预算，失败/取消与审计辅助展开均入账。Runtime 请求观测已接入根捕获/等待、worker 终止、主线程接纳/提交及 CTS 清理；真实显示与网络仍不在代码层证明范围。

- `RouteResourceLedger` 已将已兑现资源按搜索根区分：精确续用快照和新根重评基线扣除过去回合的成长/实际保命等累计值，受伤与回复分账，遗物最终计数不相减。仍需统一不同深度的评价窗口及尾部估值。

## 比较合同

1. 固定当前三回合与旧评分为 A；仅恢复改动为 B；统一估值的固定深度为 C；同一估值下选择性深入为 D；承伤策略另作 E。每次只回答一个变更的效果。
2. 不直接比较不同预测深度的累计掉血。完整闭环使用同一段战斗评价；候选比较补齐共同窗口或使用经验证的末态价值。已经模拟兑现的收益不重复加入未来估值。
3. 第一张能执行的预览、通过完整政策审核的发布和最终完成是不同时间点；离线 callback 时间不是 UI 响应时间。冷启动与热身后分开，不以第一次 JIT 耗时作为优化收益。
4. 共享预算覆盖重放、补搜和审计。分别统计停止扩展后的作业排空，不承诺软预算等于硬实时端到端截止。
5. 旧前缀只能作为建议；从新根重新证明合法性、后态及质量。取消/过期结果不能复活；仅合法不意味着更优。最终默认接纳策略需保留现有安全和多人能力边界。
6. 调参前冻结验收场景及性能门槛；质量差异逐例解释。至少覆盖连续输出、停止出牌、目标变化/死亡、增益、共享 RNG 和多次交错；脚本在各自当前状态验证动作合法性。

## 本次整理后的决策

三回合保留为深入上限（当前回合及后两回合），暂不改成统一一回合，也不要求所有候选都模拟满三回合。先解决重复计算和主线程等待，再统一不同深度的评价，最后改变深度分配。三回合是否划算，由第三回合改变最终选择的次数、闭环收益和新增成本共同判断，不能只看搜索返回了多长的路线。

不预测队友具体牌序。规划只依据已确认的战斗状态；队友尚未造成的伤害、增益和救场不能算作确定收益。自身已建立的力量、持续能力、保留资源等应保留跨回合价值，依赖某个敌人存活或队友配合的收益则需要单独处理。不能对所有未来收益统一施加强惩罚，否则会再次偏向即时防御。

搜索速度、动作安全和长期最优是三个不同目标。可以约束计算预算和接纳条件；未知队友行动下无法保证全局最优。每次只执行当前获准的动作范围，后续路线保留为可重新评估的建议，不因为模拟到了第三回合就提前承诺整条路线。

## 下一批：统一跨回合评价

P1 的后台恢复、共享预算和完整候选传递已完成代码层实现；P0 的请求观测也已接入。P2 已先修正已兑现资源的根切换口径，下一批继续共同评价窗口与末态尾部估值；保持深度分配、Beam 宽度、并行和承伤策略不变。观测器合同及原生模型重放仍不代表 Controller/UI 或原生队友动作闭环。

| 顺序 | 改动范围 | 必须满足的接纳条件 |
|---|---|---|
| P2a 收益口径 | 已实现受伤/回复、已兑现成长及实际保命的逐回合账本；已核对药水剩余成本与遗物最终计数。继续核对末态战略值覆盖的未来时间范围 | 新根历史成本不重计，模拟已兑现效果不再作为未来奖励；不能把缺失值当作零或等价 |
| P2b 共同评价窗口 | 为不同深度候选建立同一战斗窗口的比较口径，优先复用已有战略值和跨回合保留机制 | 短路线不能凭少经历一轮受伤压过完整路线；终局胜利可提前结束窗口；不放宽既有生存、药水、成长等正式接纳条件 |
| P2c 延迟收益回归 | 固定启动、持续收益、保留资源、延迟爆发、必须防御及药水生成成本场景 | 逐例解释候选排名变化，独立重放核对可兑现部分，尾部估值与实际延长模拟对照 |
| P2d 同预算对照 | 先在固定三回合下比较旧评价与统一评价，再允许 P3 改变深度分配 | 分开评价变化与调度变化；保留必胜/保命路线，不扩大计算预算，不同时修改承伤换节奏 |

已有边界继续有效：根捕获 barrier 后验证战斗、回合及状态；失效结果不能因自动请求去重而复活；计算沿用现有 worker、完成回调、取消和 CTS 所有权。跨回合恢复将成长/保命累计要求移到当前根后再严格比较；遗物末态仍保持原口径。缺少资源检查点或累计关系不一致时拒绝相应旧证明，不能通过忽略差异提高命中率。

## 选择性深入的实现原则

- 当前回合保留足够广的合法候选，并显式保留即时输出、持续收益、延迟爆发和保命等不同打法的代表。分组与配额必须有固定夹具支持，不能只按当前掉血或即时分截断。
- 二、三回合沿用同一请求的剩余预算。优先深入会影响首动作选择、存在延迟收益，或需要消除生存疑问的候选；预算紧张时先停止低价值扩展。
- 可发布结果必须独立通过既有质量检查；后台深入有改进再替换。不能为追求首结果时间，将合法但尚未审核的前缀升级成正式结果。
- 不同深度先统一比较窗口或验证末态估值，再进行排名。持续效果在尚未模拟的尾部估值，已经兑现的伤害、格挡、成长和药水成本不重复计入。
- 队友事件使动作失效时立即停止相关执行；重新计算可合并已发生的连续更新。沿用现有状态归因与稳定读合同，不通过忽略更新或放宽身份检查制造速度收益。

## 离线验收的最低通过条件

先固定对照场景、种子、预算及队友策略，再调参数。代码层验证分为两组：固定根用于定位结果/工作差异；原生队友动作脚本用于多次重新决策的闭环比较。各版本运行相同的队友策略，策略根据各自当前状态选择合法动作；不能强制相同牌序作用于已经分叉的战斗状态。

正确性要求：不修改 live 战斗状态；失效/取消结果零接纳；返回路线独立重放一致；强制药水、成本账本、生存边界和终局截断保持正确。预算账本覆盖失败与取消成员，并区分逻辑工作、线程累计时间与请求墙钟。

质量要求：在预先保留的验证场景上逐例比较胜负、死亡、战损、回合和资源，增加死亡或丢失既有必胜路线不能用平均提速抵消。尚未统一评价窗口时，不得把浅搜索少承受一轮伤害报告为质量提升。

性能要求：分别比较首次正式发布、恢复及最终完成的 P50/P95，同时报告重启次数、取消排空和作废工作。必须在相同预算、相同质量口径下观察到收益；不能仅凭“94 项检查通过”、单次热身耗时或展开节点减少就宣布提速。代码层证据覆盖到哪里就报告到哪里，真实 UI 响应和 Host/Client 仍保留为独立验证边界。

## 当前证据与发现

`U0U1PinnedHarness multiplayer-refresh` 通过原版模型建立两个玩家，使用生产 Coordinator 与刷新计算，对所有已返回路线独立重放。连同跨回合预算、请求观测、完整备选和资源口径部分，当前共报告 399 项检查、58 次独立重放。同回合部分覆盖真实后台线程上的完整路线恢复、嵌套选择集合隔离、过期原生选择拒绝、恢复失败后同预算搜索、DOP=1/4 五节点上限、1ms 时间覆盖及恢复收尾时取消。

基线 `661fccf0` 复现 6HP 时第一张已结束战斗、第二张仍重放导致 FullRestart。现已逐动作验证并截断获胜后的旧尾部，返回一张牌的完整获胜，展开节点为 0。完整备选新增 48 项检查/12 次独立重放，另补一项完整路线 Choice 集合深复制；覆盖当前/备选独立失败、第三动作失效、连续刷新、评价窗口拒绝、截止保留既有结果、候选间取消、胜利截断和禁用 HP 捷径。

12HP 固定根中，原当前路线零战损、4 动作、第 2 回合获胜；新备选零战损、2 动作、第 1 回合获胜，二者均经独立重放。对照上一请求观测构建，123、122、21、6HP 四根冷搜的动作/质量/工作均不变；恢复展开仍为 0，但重评完整备选使转移数由 11/11/5/1 增至 33/33/21/4。不能把零展开等同零成本，也不能由这个案例推断普遍提速。

`MP_PLAN_REFRESH_WORKER` 记录完整路线是否恢复、前缀阶段指标、恢复工作和剩余预算；报告的 `FullRoutes` 另保留各路线接纳/拒绝原因，`SelectedOriginalRank` 标识原候选。`MP_PLAN_REFRESH_ACCEPT` 只在普通完成回调通过过期检查后产生。失败备选不会影响可用当前路线，失效当前路线只能由在新根重新证明合规的备选替换。

当前资源账本构建的完整离线入口 24 步、36 组 L1、82 项 portfolio、17 个 pinned 模式通过，Windows/Bash 结构门禁通过。Release 0 警告/0 错误；符号链接权限子项明确跳过。DLL SHA256 为 `8385423F16EB880FF2F148EF240662167B57B1AFE642BB54E6CF9F2DB8C6DD81`。夹具使用显式 HP/回合修改，没有驱动原生队友出牌、Controller、网络或 UI；不能替代 P5 闭环脚本或 Host/Client 验收。

跨回合候选传递新增 52 项检查/11 次独立重放。真实搜索生成的两个未来续接点经独立前缀重放，再验证精确续用保留候选。第二回合原生根加合成历史记账覆盖过去药水/战损不重计、续用后同回合再刷新、完整备选替换、共同 600ms 份额、失败后 R1/DOP=1/4 节点预算及终局截断；不把合成历史当作原生 EndTurn 证据。与上一构建相比，四个固定根的冷搜及同回合恢复动作/质量/工作均相同。

资源口径新增 23 项检查/4 次独立重放：原生版税路线的两个未来续接点验证已兑现成长和 HP 抵扣不再作为未来收益；受控新回合根注入旧口径基线时复现 `alternative_growth_changed`，剩余口径下备选直接获胜，展开 1→0。保命、受伤/回复、第三方成长、机会损失与重复推进另以算术合同核对，包括“后续受伤 10、回复 10”不能被净 HP 差抹掉。该结果不是不同深度评价或普遍性能证明。四个旧固定根与上一构建的冷搜/同回合恢复动作、质量及逻辑工作均一致。

跨回合预算部分覆盖 route replay 失败后 R1 / 主搜索共用余量、DOP=1/4、40 节点上限、截止时无解与已证明胜利、取消和注入失败。真实策略身份下先填充 R1 缓存，再核对所有提前退出路径清空引用；预算节点与成员账本逐项守恒。普通对照与恢复结果的固定输入质量一致，各自返回路线独立重放一致，不要求 R1 与冷搜工作量相同。该结果不证明普遍提速。

既有 `E0PinnedHarness --p2-ab --scenario teammate` 对照也通过：冷搜、R1 和枚举提示的路线/质量相同，均在原节点预算内。冷搜和提示各为 392 展开/1030 转移，R1 为 615/1589，其中探测 223 展开。这说明预算合规不等于节省工作；后续 P0/P1 必须识别无收益的恢复尝试。单进程耗时不用于普遍性能结论，证据在 `cross-turn-budget/r1-ab-teammate/`。

请求观测补充了同一编号下的根等待/捕获、worker、preview、正式路线提交、结果接纳、取消和 callback/CTS 收尾。16 项纯生产观测器合同区分不同阶段，覆盖重复延迟、取消前未启动 Task、CTS 清理竞争及重复收尾。原生 Coordinator DOP=1/4 开关对照的完整动作、最终状态、质量和工作量相同，异常/取消工作各回传一次。未接纳请求的总展开量附带预览是否已提交，不能直接称为全量浪费。

共享预算证据保留在 `.local/multiplayer-search-plan/cross-turn-budget/`；请求观测证据在 `.local/multiplayer-search-plan/request-observation/`；同回合完整备选证据在 `full-alternatives/`，跨回合传递在 `cross-turn-alternatives/`。本批资源口径证据在 `.local/multiplayer-search-plan/resource-accounting/` 的 `full/`、`native-resources-2/` 和 `fixed-input-comparison.json`。这些代码层检查不能给出真实 UI P50/P95，也不能宣布已提速。下一批继续 P2 共同窗口及尾部估值，再进入 P3；仍不绕过过期结果/回合/世界身份的接纳合同，三回合、评分权重和并行默认未变。
