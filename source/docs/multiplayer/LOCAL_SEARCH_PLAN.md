# 多人本地搜索实施计划

目标：在不预测队友主动出牌、保持当前预算和本地执行权限的前提下，保留跨回合打法并减少外部变化造成的无效计算。用户要求先重构项目，再开始实施；当前阶段仅做代码层验证，不启动游戏。算法改动与“少量承伤换节奏”的目标函数实验分别验证，不以提高预算换取结果。

## 当前起点

- 对照提交 `19f7a559`，游戏/RitsuLib pinned 0.107.1。
- 默认 local-single-core，当前回合加后两回合，原始战损优先；队友预测/团队场景默认关闭。
- 已有跨回合候选保留、R0/R1、新根路线重放和工作统计，避免重复建设或放宽缓存键。
- 现存有界 refresh 保留最多三个不同首动作、各两张牌，重放后只物化选中的一条。物化上限 192 节点/60ms，不包含所有准备及收尾开销，当前仍在主线程同步调用。
- Search 只消费冻结根；候选建议不携带旧分数或执行授权。未知语义、身份/资源/RNG 不匹配按已有合同拒绝或新根重新模拟。

| P1 恢复 | 有界候选新根重评估，终局截断，失败候选隔离，恢复和重搜共用预算；检查主线程等待 | 原生模型逐动作重放、外部变化/取消/终局用例、同预算对照 | 已修复提前斩杀与不可用备选；后台执行、共享预算和完整候选重评估待实施 |

| P5 离线验收 | 训练/调参夹具与保留验证夹具分开；相同队友脚本驱动完整重新决策 | 胜负/战损/回合/资源、首结果与恢复延迟、作废工作和预算合规 | 待实施；Host/Client 和 UI 不在本轮证明范围 |

## 比较合同

1. 固定当前三回合与旧评分为 A；仅恢复改动为 B；统一估值的固定深度为 C；同一估值下选择性深入为 D；承伤策略另作 E。每次只回答一个变更的效果。
2. 不直接比较不同预测深度的累计掉血。完整闭环使用同一段战斗评价；候选比较补齐共同窗口或使用经验证的末态价值。已经模拟兑现的收益不重复加入未来估值。
3. 第一张能执行的预览、通过完整政策审核的发布和最终完成是不同时间点；离线 callback 时间不是 UI 响应时间。冷启动与热身后分开，不以第一次 JIT 耗时作为优化收益。
4. 共享预算覆盖重放、补搜和审计。分别统计停止扩展后的作业排空，不承诺软预算等于硬实时端到端截止。
5. 旧前缀只能作为建议；从新根重新证明合法性、后态及质量。取消/过期结果不能复活；仅合法不意味着更优。最终默认接纳策略需保留现有安全和多人能力边界。
6. 调参前冻结验收场景及性能门槛；质量差异逐例解释。至少覆盖连续输出、停止出牌、目标变化/死亡、增益、共享 RNG 和多次交错；脚本在各自当前状态验证动作合法性。

## 当前证据与发现

`U0U1PinnedHarness multiplayer-refresh` 通过原版模型建立两个玩家，使用生产 Coordinator 与刷新计算，对所有已返回路线独立重放。四个受控 HP 根为 123、122、21、6，当前报告 94 项检查、12 次独立重放；涵盖当前路线缺失/不可用、备选不可用、错误回合和取消拒绝。

基线 `661fccf0` 复现 6HP 时第一张已结束战斗、第二张仍重放导致 FullRestart。现已逐动作验证并截断获胜后的旧尾部，返回一张牌的完整获胜，展开节点为 0。四个根的新搜索结果与旧基线一致，前三个普通刷新场景的动作、质量和逻辑工作一致。失败备选不会影响可用当前路线；失效当前路线仍不允许未经质量验收地替换。

`MP_PLAN_REFRESH_PHASE` 记录尝试/拒绝/截断候选、前缀转移数，以及前缀/物化/总耗时。初始样本前缀约 1–3ms，主要开销在补充物化；60ms 是软搜索限制，收尾使总耗时可能超出。上述单次耗时不是稳定性能结论，也不是主线程响应或整个请求预算已改善的证明。

当前完整离线入口 24 步、35 组 L1、82 项 portfolio、17 个 pinned 模式和 Windows/Bash 结构门禁通过。符号链接权限子项明确跳过。夹具使用显式 HP 修改，没有驱动原生队友出牌、Controller、网络或 UI；不能替代 P5 闭环脚本或 Host/Client 验收。完整输出在 `.local/multiplayer-search-plan/prefix-repair/full-verified/` 和 `final-refresh/`（最后所有权收尾修正后的专项复跑）。

下一批：沿已有后台搜索生命周期接入恢复计算；把完整保留路线的新根重放及其既有质量验收与共享预算衔接，并建立同预算对照。不得只把同步代码包入无人拥有的 Task，也不得绕过过期结果/回合/世界身份的接纳合同。

## 离线入口

在仓库根运行：

```powershell
dotnet build source/CombatSolver.csproj -c Release -p:CopyModOnBuild=false
dotnet run --project source/tools/U0U1PinnedHarness -c Release -- multiplayer-refresh --out .local/multiplayer-search-plan/refresh
```

组合验证沿用 [run-offline-validation.ps1](../../tools/run-offline-validation.ps1) 和 [测试矩阵](../TEST_MATRIX.md)。新夹具初期独立运行，稳定后再纳入组合入口。职责真源见 [架构](../ARCHITECTURE.md)。
