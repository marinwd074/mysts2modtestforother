# 多人本地搜索实施计划

目标：在不预测队友主动出牌、保持当前预算和本地执行权限的前提下，保留跨回合打法并减少外部变化造成的无效计算。用户要求先重构项目，再开始实施；当前阶段仅做代码层验证，不启动游戏。算法改动与“少量承伤换节奏”的目标函数实验分别验证，不以提高预算换取结果。

P2 已落实评价范围信息、同窗口用药比较和非终局恢复的阶段检查；普通候选的全局排序、同窗口补齐、尾部估值及选择性深入仍未完成。用户最新要求“减少测试”：每批只运行直接覆盖改动的定向检查，复用已有夹具；不重复全量回归、不为收集统计反复测速，也不把历史 PASS 写成本轮验证结果。

## 单人与多人共用的边界

单人继续完整战斗预测，不套用多人三回合限制，也不以缩短预测范围作为提速手段。完整预测指搜索目标保持到战斗结束，仍受已有时间、节点和语义边界约束；预算耗尽的未完成路线不能标为完整预测结果。

- 共用模拟器、主搜索、资源账本、评价范围、缓存、恢复和预算机制；新增能力优先接入这些已有入口。多人只增加真实状态观察、本地执行权限及对应策略，不另建一套评分或搜索引擎。
- `SearchEvaluationPolicy` 统一提供预测层数与质量优先级：单人无固定回合上限，默认多人为当前回合加后两回合。`RouteEvaluationWindow` 用空目标表示完整战斗，用有限目标表示滚动窗口；两者不能直接混算成本。
- 本批已合并预览的共同排序流程，并让 Beam、无药水基线和 Coordinator 共用胜负/生存/保命消耗的前置比较。单人仍胜利优先；修复资源回收比较暗中覆盖多人原始战损顺序的问题。完整的不同窗口排序仍属于 P2 后续工作。
- 提速先使用准确状态下的缓存、已有路线的新根重评、重复状态消除和可证明的剪枝；保留当前最佳完整路线，后台改进只在同一质量口径下接纳。不得把减少模拟深度或漏算未来风险记为等质提速。
- P3 的二/三回合预算分配仅适用于默认多人。单人可共享候选调度和复用实现，但继续向战斗结束搜索；不能因共用调度器引入三回合截止。质量与速度分别记录，固定输入下优先核对完整路线质量和实际计算工作，必要时再计时。

## 比较合同

1. 历史的固定三回合/旧评分为 A，恢复和资源记账后的当前实现为 B；下一批只对照 B 与统一估值、保持原深度调度的 C，再对照 C 与选择性深入 D；承伤策略另作 E。每批只回答一个变更的效果，不重跑完整 A—E 矩阵。
2. 不直接比较不同预测深度的累计掉血。完整闭环使用同一段战斗评价；候选比较补齐共同窗口或使用经验证的末态价值。已经模拟兑现的收益不重复加入未来估值。
3. 第一张能执行的预览、通过完整政策审核的发布和最终完成是不同时间点；离线 callback 时间不是 UI 响应时间。冷启动与热身后分开，不以第一次 JIT 耗时作为优化收益。
4. 共享预算覆盖重放、补搜和审计。分别统计停止扩展后的作业排空，不承诺软预算等于硬实时端到端截止。
5. 旧前缀只能作为建议；从新根重新证明合法性、后态及质量。取消/过期结果不能复活；仅合法不意味着更优。最终默认接纳策略需保留现有安全和多人能力边界。
6. 调参前冻结代表性场景、预算和接纳口径；质量差异逐例解释。沿用已有连续输出、停止出牌、目标变化/死亡、增益、共享 RNG 和交错检查，只为本批行为缺口补场景；脚本在各自当前状态验证动作合法性。

## 本次整理后的决策

三回合保留为深入上限（当前回合及后两回合），暂不改成统一一回合，也不要求所有候选都模拟满三回合。已有恢复和请求观测作为起点，下一步先统一不同深度的评价，再改变深度分配。三回合是否划算，由第三回合改变首动作选择的次数、闭环收益和新增成本共同判断，不能只看搜索返回了多长的路线。

不预测队友具体牌序。规划只依据已确认的战斗状态；队友尚未造成的伤害、增益和救场不能算作确定收益。自身已建立的力量、持续能力、保留资源等应保留跨回合价值，依赖某个敌人存活或队友配合的收益则需要单独处理。不能对所有未来收益统一施加强惩罚，否则会再次偏向即时防御。

队友没有继续行动只能是本地模拟的条件，不能宣称是所有可能队友行为下的安全下界。未知动作仍可能改变目标、抽牌或共享 RNG；真实事件到来后，用新根重新验证当前动作及少量备选。已经获准的动作范围之外，未来路线仍是建议。

过于保守和计算太慢有不同成因。共同窗口先排除“少模拟一轮所以少掉血”的假优势；选择性深入节省计算。如果同一窗口内仍因原始战损优先而拒绝少量承伤换取更早结束战斗，这是 P4 的目标函数问题，单靠缓存和减少搜索深度不会解决。

搜索速度、动作安全和长期最优是三个不同目标。可以约束计算预算和接纳条件；未知队友行动下无法保证全局最优。每次只执行当前获准的动作范围，后续路线保留为可重新评估的建议，不因为模拟到了第三回合就提前承诺整条路线。

方案采用有限前瞻、末态估值和滚动重算的组合，概念参考 [Bertsekas 的 MPC / rollout 讲义](https://stuff.mit.edu/~dimitrib/RLTopics_2021_Lect3.pdf)。这是实现方向参考；本项目的近似搜索、未知队友和软预算不满足直接套用最优性或稳定性保证的前提。

## 下一批：统一跨回合评价

P1 的后台恢复、共享预算和完整候选传递已完成代码层实现；P0 的请求观测也已接入。P2 已先修正已兑现资源的根切换口径，下一批继续共同评价窗口与末态尾部估值；保持深度分配、Beam 宽度、并行和承伤策略不变。观测器合同及原生模型重放仍不代表 Controller/UI 或原生队友动作闭环。

| P2c 延迟收益回归 | 固定启动、持续收益、保留资源、延迟爆发、必须防御及药水生成成本场景 | 逐例解释候选排名变化，独立重放核对可兑现部分，尾部估值与实际延长模拟对照 |
| P2d 同预算对照 | 先在固定三回合下比较旧评价与统一评价，再允许 P3 改变深度分配 | 分开评价变化与调度变化；保留必胜/保命路线，不扩大计算预算，不同时修改承伤换节奏 |

已有边界继续有效：根捕获 barrier 后验证战斗、回合及状态；失效结果不能因自动请求去重而复活；计算沿用现有 worker、完成回调、取消和 CTS 所有权。跨回合恢复将成长/保命累计要求移到当前根后再严格比较；遗物末态仍保持原口径。缺少资源检查点或累计关系不一致时拒绝相应旧证明，不能通过忽略差异提高命中率。

### P2 的具体落点与完成条件

1. **先加评价范围，暂不改变排序。** 候选记录搜索根、已结算的敌方回合/阶段、目标结束边界和终局状态。`Snapshot.Turn` 只说明模拟到了哪个回合，不能单独代表该回合已经结算。已模拟受伤、回复、药水成本、成长继续使用现有账本；未知尾部明确标为未模拟。
2. **统一所有质量比较入口。** 覆盖 `CombatBeamSolver.FinalPlanOrdering`、`SolverInterimResultOrdering`、`CombatSearchCoordinator.ResultPolicy`、无药水基线和恢复接纳。不能只修最终排序，让预览或 Smart 药水判断继续把不同窗口的掉血相减。比较器仅比较范围一致的质量；跨窗口由调度处理，避免两两特判造成非传递排序。
3. **按同一边界比较，按剩余预算补齐。** 同窗口保留现有生存、保命消耗、战损和资源规则。提前完全获胜视为剩余窗口没有后续战斗成本。对可能改变首动作的短路线，用已有模拟器和有界续接推进到共同边界；费用纳入原请求预算。不完整路线不能仅凭少掉血或较浅的“未死亡”状态宣布更优，也不能把“更深”作为质量奖励。补不齐时保留已审核结果；没有合格结果时沿用现有无结果/预览边界。
4. **最后校准末态价值。** `StrategicEffectModel` 当前按敌人 HP、牌堆和预计攻击估计剩余回合，需与明确的评价边界衔接。已经模拟兑现的能力收益不再计算；尚未兑现的力量、持续效果、保留牌/能量按相同未来范围估值。三回合之外仍可保留有界的启发式余值，避免把长启动牌直接判作无价值；余值不得伪装成已恢复 HP、已避免受伤或已满足药水使用条件。敌人绑定收益与自身持续状态分开，不预支队友伤害。

第一项范围信息及第二项中的用药/恢复比较已实现，短用药路线对长基线的反例已定向验证。普通全局最终排序、`SolverInterimResultOrdering` 和 Coordinator 跨成员优选尚未统一；下一次继续这些入口与有界补齐，随后处理末态价值。只补直接触及的行为缺口，不重复跑已通过夹具或另建与实现逐句对应的测试。

P2 完成意味着固定原深度调度下，所有入口使用一致的比较口径，并能解释延迟收益案例的变化。仅新增字段、日志或深度优先排序不能算完成；未进入 P3 前不同时改 Beam 宽度、深入配额或承伤权重。

## 选择性深入的实现原则

- 当前回合保留足够广的合法候选，并显式保留即时输出、持续收益、延迟爆发和保命等不同打法的代表。分组与配额必须有固定夹具支持，不能只按当前掉血或即时分截断。
- 在现有总宽度内保留代表，不额外扩 Beam。同一首动作的大量相似后续先合并为少量代表，把预算留给真正不同的当前决策；只对等价状态做安全去重，不把共享首动作误当作后态等价。
- 二、三回合沿用同一请求的剩余预算。优先深入会影响首动作选择、存在延迟收益，或需要消除生存疑问的候选；预算紧张时先停止低价值扩展。
- 第三回合主要用于分辨前两名、验证启动收益/延迟爆发和解决尚未确定的生存边界。只有已证明的优势可以作为安全剪枝依据；启发式收益只能调整计算优先级。先做一个简单调度版本，不同时引入队友模型、学习模型或复杂自适应参数。
- 可发布结果必须独立通过既有质量检查；后台深入有改进再替换。不能为追求首结果时间，将合法但尚未审核的前缀升级成正式结果。
- 不同深度先统一比较窗口或验证末态估值，再进行排名。持续效果在尚未模拟的尾部估值，已经兑现的伤害、格挡、成长和药水成本不重复计入。
- 队友事件使动作失效时立即停止相关执行；重新计算可合并已发生的连续更新。沿用现有状态归因与稳定读合同，不通过忽略更新或放宽身份检查制造速度收益。

记录每层的新增工作、是否改变首动作、是否改善已审核结果；P3 只与相同评价函数的 P2 比较。恢复尝试也要统计成本，已有证据表明 R1 或重评更多备选可能增加工作；先依据少量固定场景判断是否值得，再决定是否缩短无收益的恢复尝试，不默认“复用一定快”。

## P4：保守程度单独处理

P2/P3 保持原始战损优先。P4 使用独立实验开关，只在共同窗口和相同预算下比较：允许的额外承伤、提前结束收益以及保留资源的价值。先复用“零损失但拖长”和“少量损失但更早获胜”的代表输入；死亡、保命消耗、强制药水和资源约束仍单列，不由平均得分抵消。

不预设统一减伤权重或固定承伤比例。先确认当前保守表现来自哪条排序规则，再选一个最小、可回滚的权衡；不因本地估值假定队友会补足斩杀。实验结果与纯提速结果分别报告。

## 离线验收的最低通过条件

先固定少量代表性场景、种子、预算及队友策略，再调参数。代码层验证分为两组：固定根用于定位结果/工作差异；原生队友动作脚本用于多次重新决策的闭环比较。闭环夹具在开始调度实验前准备，避免最后才发现优化只对静态根有效。各版本运行相同的队友策略，策略根据各自当前状态选择合法动作；不能强制相同牌序作用于已经分叉的战斗状态。

正确性要求：不修改 live 战斗状态；失效/取消结果零接纳；返回路线独立重放一致；强制药水、成本账本、生存边界和终局截断保持正确。预算账本覆盖失败与取消成员，并区分逻辑工作、线程累计时间与请求墙钟。

质量要求：在预先保留的验证场景上逐例比较胜负、死亡、战损、回合和资源，增加死亡或丢失既有必胜路线不能用平均提速抵消。尚未统一评价窗口时，不得把浅搜索少承受一轮伤害报告为质量提升。

性能要求：先用少量成对固定输入检查正式发布、恢复及最终完成时间，并报告重启、取消排空和作废工作。样本不足时只报告逐例结果，不为凑 P50/P95 反复运行；已有足够样本时才报告分布。必须在相同预算、相同质量口径下解释收益，不能仅凭检查数量、单次热身耗时或展开节点减少就宣布普遍提速。代码层证据覆盖到哪里就报告到哪里，真实 UI 响应和 Host/Client 仍保留为独立验证边界。

### 缩减后的验证安排

| 改动 | 本批验证 | 何时才扩大范围 |
|---|---|---|
| 计划、文档 | 差异与相关链接检查 | 不构建、不跑战斗回归 |
| P2 评价合同/排序 | 一次 Release；复用并运行直接受影响的窗口、终局、持续效果及药水对照用例；返回路线独立重放 | 发现共用排序或账本回归时，扩大到对应入口 |
| P3 调度 | 一次 Release；少量固定根成对对照，加一个代表性的队友交错闭环；核对预算和首动作变化 | 出现质量下降、取消/预算异常时，补对应场景 |
| P4 评分 | 复用已有输入，仅对照开关；核对承伤、结束回合与资源 | 发现新的生存或资源风险时，定向增加 |
| 阶段收尾 | 汇总已获得证据和缺口 | 仅在实际影响面要求时运行一次相关组合检查，不默认重跑完整矩阵 |

已有混沌药水、候选恢复、取消、资源账本等检查保持可运行；代码未触及其行为时不重复执行。失败后先定位根因，只重跑相关检查；新失败揭示更广影响时再扩展。减少重复验证不改变“未知不能按已通过处理”的证据口径。
